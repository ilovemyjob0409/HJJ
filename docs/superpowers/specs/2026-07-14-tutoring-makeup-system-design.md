# 補習班補課/調課系統 — 設計文件

日期：2026-07-14

## 背景與目標

單一分校小型補習班（幾位老師、幾十位學生）目前用 LINE 群組/聊天輯處理請假、調課、補課，容易漏接、難以追蹤狀態。此系統目標是把三種情境數位化：

1. 學生請假
2. 學生補課（插班或一對一）
3. 老師請假/調課（代課安排）

系統**不**取代現有的班級/課表維護方式，而是在其上加一層「例外事件」管理。班級、學生、老師的基本名單改為在本系統中手動維護（原本存於 Excel/Google 表單），但不建立完整排課引擎。

## 範圍外（Out of Scope）

- 完整課表/排課引擎（無堂次自動產生、無教室管理）
- 班級人數上限強制限制（僅顯示目前人數供參考）
- LINE 通知或 Email 主動推播（使用者登入後查看狀態即可）
- 多分校/跨分校管理

## 角色與權限

| 角色 | 帳號 | 權限 |
|---|---|---|
| 行政/教務人員 | 帳號密碼 | 維護班級/學生/老師名單；查看所有請假/補課/代課申請；核准補課申請（插班與一對一）；指派代課老師 |
| 老師 | 帳號密碼 | 查看自己任教班級與請假名單；提出自己的請假/調課申請；設定每週固定可補課時段（一對一用） |
| 學生/家長 | 帳號密碼（或學號+手機末幾碼簡化登入） | 提出請假申請（自動核准）；申請補課（插班或一對一，需行政核准）；查看自己所有申請狀態 |

## 資料模型

### 基本名單（手動維護，取代原 Excel）

- **Teacher**：姓名、聯絡方式、任教科目
- **Student**：姓名、聯絡方式、家長聯絡方式、登入帳密
- **Class**：班名、科目、等級、老師、上課星期＋時間、目前人數（供參考）
- **ClassEnrollment**：學生與班級的固定隸屬關係

### 一對一補課用

- **TeacherAvailability**：老師、星期幾、開始時間、結束時間（老師自行設定的每週固定可補課時段，可隨時編輯）

### 例外事件（只在事件發生時建立紀錄，不建立每日堂次資料）

- **LeaveRequest**（學生請假）：學生、班級、請假日期、原因、狀態（送出即自動核准）
- **MakeupRequest**（補課申請）：關聯到某筆請假、申請類型（插班／一對一）
  - 插班：目標班級、目標日期
  - 一對一：老師、具體日期/時間（須落在該老師的 TeacherAvailability 範圍內）
  - 狀態：待行政確認／已核准／已拒絕
- **SubstituteRequest**（老師請假/代課）：班級、原訂日期、原因、代課老師、狀態

## 核心流程

### 流程一：學生請假

1. 學生/家長登入 → 選擇班級與請假日期 → 填寫原因 → 送出
2. 系統自動核准，狀態顯示「已請假」
3. 行政與該班老師都能在後台看到此紀錄

### 流程二：補課申請

學生在請假紀錄旁可申請補課，分兩種類型：

**A. 插班補課**
1. 系統列出同科目、同等級的其他班級（顯示時間、目前人數供參考）
2. 學生選擇班級與日期 → 送出，狀態為「待行政確認」
3. 行政人工判斷進度是否合適 → 核准或拒絕
4. 核准後，學生與該班老師都能看到插班紀錄

**B. 一對一補課**
1. 系統檢查該學生本季（自然月季度：1-3月／4-6月／7-9月／10-12月）是否已有「待行政確認」或「已核准」的一對一補課申請（每季限一次）→ 若有則不可再申請，顯示原因（若該筆申請後續被行政拒絕，名額即釋放，可再次申請）
2. 學生選擇一位教該科目的老師 → 系統顯示該老師的每週固定可補課時段 → 學生選擇落在時段內的具體日期/時間
3. 系統檢查該時段是否已被其他學生佔用（待審或已核准中）→ 衝突則不可選取
4. 送出後狀態直接為「待行政確認」（不經老師逐件審核）
5. 行政核准或拒絕 → 核准後名額維持已使用；拒絕則名額釋放

兩種申請類型共用同一份「補課申請」清單與審核介面，行政人員在同一處處理。

### 流程三：老師請假/調課（代課安排）

1. 老師登入 → 選擇任教班級與請假日期 → 填寫原因 → 送出
2. 行政人員在「待安排代課」清單中指派代課老師 → 班級時間不變，學生不受影響
3. 系統顯示該堂課「原老師／代課老師」，老師與行政皆可查看

所有流程皆不主動推播通知，使用者登入後於自己的清單/狀態頁查看最新狀況。

## 主要畫面規劃

**行政人員**
- 儀表板：待處理事項（待審補課申請、待安排代課）
- 班級/學生/老師名單管理
- 請假/補課/代課總覽（可依班級、日期、狀態篩選）

**老師**
- 我的班級與課表（含請假學生、代課異動）
- 請假/調課申請表單
- 設定我的每週可補課時段

**學生/家長**
- 我的請假/補課申請記錄與狀態
- 請假申請表單
- 補課申請表單（插班或一對一，一對一會檢查名額與時段衝突）

## 技術棧

- **Next.js + TypeScript**：前後端同一專案，React 介面 + API Routes 後端邏輯
- **資料庫**：SQLite（透過 Prisma ORM），小規模免額外架設，日後可換 Postgres
- **驗證**：帳號密碼登入（session-based），三角色共用登入機制，依角色導向不同畫面
- **部署**：先本機/單一伺服器，之後視需要上雲端（如 Vercel + 雲端資料庫）
