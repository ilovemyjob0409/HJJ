# 補習班補課系統 UI/UX 改版 — 設計文件

日期：2026-07-15

## 背景與目標

現有系統（[2026-07-14-tutoring-makeup-system-design.md](2026-07-14-tutoring-makeup-system-design.md)）功能已全數完成並通過審查，但視覺上只有最基礎的黑底白字、裸表格、裸表單，尚未考慮實際使用體驗。使用者計畫未來將系統開放給家長透過網址直接使用，因此希望在正式對外部署前，先讓介面更貼近教育類產品應有的親和、專業觀感。

參考網站：[HJJ GO（黑嘉嘉圍棋課程平台）](https://app.heijiajia.com.tw) 登入頁的視覺語言（暖色調、圓角、左右分割版面），僅取其視覺風格，不涉及任何程式邏輯抄襲。

## 範圍

- **涵蓋全部 13 個既有畫面**：登入頁、行政 6 頁（儀表板、老師/學生/班級名單、補課申請審核、代課安排）、老師 3 頁（儀表板、可補課時段設定、請假申請）、學生 3 頁（儀表板、請假申請、補課申請）。
- **不涉及**：資料庫結構、API、權限邏輯、業務規則（一對一補課名額/衝突檢查等）——這些在前一份設計文件中已完成且通過審查，本次不重新驗證。
- **新增行為**（非單純換皮）：所有登入後頁面加上共用頂部導覽列，讓使用者能在功能頁與自己的儀表板之間切換，不必依賴瀏覽器上一頁。

## 視覺規範（Design Tokens）

| 用途 | 值 |
|---|---|
| 主色（按鈕、重點強調） | `#FFBD5A`（琥珀金） |
| 品牌背景色 | `#FFF1DE`（暖米色） |
| 主要文字色 | `#3a332b`（暖黑，非純黑） |
| 次要文字色 | `#8a7f70` |
| 狀態色 — 待處理 | 橘 `#F2994A` / 背景 `#FFF3E0` |
| 狀態色 — 已核准/成功 | 綠 `#6FCF97` / 背景 `#E8F8EE` |
| 狀態色 — 已拒絕/取消 | 紅 `#EB5757` / 背景 `#FDECEC` |
| 狀態色 — 已指派 | 藍 `#2C5FBB` / 背景 `#EAF2FF` |
| 圓角 — 卡片 | 10–12px |

這些值會加進 `tailwind.config.ts` 的 `theme.extend.colors`，供全站元件引用，不在個別頁面裡硬寫顏色碼。

## 共用元件（`src/components/ui/`）

新增以下元件，取代目前每頁各自重複的 Tailwind 類別組合：

- **`Button`**：`variant="primary"`（琥珀金底、白字）／`variant="secondary"`（白底、邊框）
- **`Input`**：統一圓角與 focus 樣式，包裝原生 `<input>`
- **`Card`**：白底、陰影、圓角容器，取代裸表格外層
- **`StatusBadge`**：將現有狀態列舉值對應為中文圓角標籤
  - `APPROVED` → 綠色「已核准」
  - `PENDING_ADMIN` / `PENDING_ASSIGNMENT` → 橘色「待確認」
  - `REJECTED` → 紅色「已拒絕」
  - `ASSIGNED` → 藍色「已指派」
- **`DataTable`**：統一表格外觀（表頭文字色、列分隔線、間距），套用在老師/學生/班級名單、審核佇列等清單頁
- **`AppShell`**：包住每個登入後頁面的共用外框，內含頂部導覽列

這些元件只負責呈現，不含業務邏輯；每個既有頁面的資料抓取（`fetch('/api/...')`）與狀態管理維持原樣，只是把渲染的 JSX 換成呼叫這些元件。

## 導覽列（AppShell）

套用在所有登入後頁面（`/admin/*`、`/teacher/*`、`/student/*`），取代目前每頁各自獨立、無法互相導覽的狀況：

- 左側：系統名稱（可點擊，導回自己角色的儀表板 `/admin`、`/teacher`、`/student`）
- 右側：依角色顯示對應功能連結
  - 行政：老師名單／學生名單／班級名單／補課申請／代課安排
  - 老師：請假/調課申請／設定可補課時段
  - 學生：請假申請／補課申請
- 最右側：登出按鈕（呼叫 NextAuth `signOut()`）

`AppShell` 內部透過 `useSession()` 或由頁面傳入 `role` 判斷要顯示哪一組連結；不重新設計權限邏輯，畫面能不能進入仍由既有的 `src/middleware.ts` 把關。

## 版面規則

- **桌面（≥768px）**：登入頁維持左右分割（左側品牌色塊＋插畫佔位、右側白色表單卡片）；其餘頁面採 `AppShell` 導覽列＋內容區塊
- **手機（<768px）**：登入頁改為單一置中白色表單卡片（無品牌色塊），避免分割版面在窄螢幕上跑版；其餘頁面的 `AppShell` 導覽列在窄螢幕下功能連結需可換行或收合，但不強制做成漢堡選單抽屜（YAGNI，畫面數量少，直接換行即可）

## 實作與驗證方式

- **不動商業邏輯**：本次僅改動 UI 層（元件、樣式、頁面結構的視覺呈現），API 路由、Prisma 查詢、權限檢查、業務規則一律不變
- **既有測試維持通過**：現有 36 個 Vitest 測試（服務層）不受影響，應維持全數通過；`npx tsc --noEmit`／`npx next build` 需維持乾淨
- **不新增自動化 UI 測試**：現有專案沒有元件測試機制，本次改版不引入新的測試框架，驗證方式為建置檢查＋瀏覽器手動走過三種角色的完整流程（沿用先前任務驗證時使用的流程與種子帳號）
- **文字內容不變**：所有現有的中文文案、表單欄位、按鈕文字維持原樣，只換視覺呈現，避免這次改版意外變更使用者已經熟悉的操作文字

## 範圍外（Out of Scope）

- 不做深色模式（dark mode）
- 不做多語系
- 不重新設計資訊架構（頁面清單、路由結構維持不變）
- 不做漢堡選單／側邊抽屜導覽（畫面數量少，用不到）
- 不修改任何 API、Prisma schema、業務邏輯或權限規則
